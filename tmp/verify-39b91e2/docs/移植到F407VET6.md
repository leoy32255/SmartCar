# 移植到 STM32F407VET6：当前状态

当前硬件为用户确认的XY-160D修订3，已经完成保持停车的F407板级最小构建。执行 `make` 或 `make MCU_FAMILY=F4`；具体依赖、工具链、产物、时钟、中断和验证范围见 [F407最小构建](F407最小构建.md)。

## 已完成

- 固定真实ST HAL、CMSIS Device及Arm CMSIS Core，含许可证、哈希清单、官方启动和SystemInit。
- 512KiB Flash、128KiB SRAM链接脚本；另64KiB CCM不合并计入连续SRAM。
- 8MHz HSE ->168MHz，Scale1、Flash 5 WS，F407不使用OverDrive。
- TIM1 PE9/11 2kHz零占空比，TIM3/TIM4编码器，TIM6 5ms，SysTick HAL 1ms。
- SPI2 PB13/14/15，CS PB12/PE7；USART2 PD5/6；PB10 EXTI10；方向PE8/10/12/13保持11。
- 当前入口与ISR位于Core/F407，Makefile排除旧应用源文件，避免中断重复定义和TIM4冲突。

## 后续实现

旧F103业务不能直接搬入本目标：XY-160D的方向11为高阻滑行、00为刹车，与旧TB6612语义不同；共享SPI2需要完成IMU及MCP23S17驱动，循迹不再直读MCU GPIO。完整控制、心跳超时、异常锁存与人工重启、蓝牙面板按spec后续实现，不能用最小构建成功宣称已交付。

PA0按键与PA1 LED只保留，不推断板载极性。板载SPI器件占用、编码器CPR及电机方向需现场核验。

## 下载路径更正

首次计划使用芯片系统存储器内置ROM USB DFU，不需要在应用中加入USB DFU类，也不依赖ST-Link。实际BOOT跳帽/按键流程依据板级资料核验；具体操作边界与ST官方来源见 [F407最小构建](F407最小构建.md#后续rom-dfu路径)。本轮未下载、未运行电机，未验证DFU枚举或实车表现。
