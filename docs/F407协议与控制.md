# F407课堂协议与控制 v1

当前实现：Core/F407/{app,control,runtime,uart,sensors,sensor_port}.c。旧README中的F103协议和13字节遥测不适用。USART2 PD5/PD6，9600、8N1；所有多字节整数小端、有符号量采用二补码。

## 帧与命令

`AA 55 CMD LEN PAYLOAD CHECKSUM`，CHECKSUM为CMD+LEN+PAYLOAD字节累加的低8位。最大载荷48字节；解析帧起点至后续字节超过100ms则丢弃部分帧。坏校验、超长、未知命令不能续心跳；合法但长度不符命令被拒绝。ACK只代表命令接受，实际状态看遥测。普通命令从首字节收到至处理超过100ms拒绝；STOP始终允许。RX/TX各256字节，RX溢出/硬件错误锁存停车；TX不足整帧丢弃并计数，不等待串口。

| CMD | Payload | 行为 |
|---|---|---|
| 01 | u8模式 | 0 STOP、1循迹、2遥控；无其他运动模式。诊断固件拒绝1/2 |
| 02 | i16左、i16右 | 遥控目标，counts/10ms，各-10..10；仅遥控模式接受 |
| 03 | u8参数ID、i16值 | 仅停车可改，ID0基础速度0..20；ID1..5循迹Kp/Kd、速度Kp/Ki/Kd，各0..200 |
| 04 | 空 | 停车且IMU有有效样本时申请校准，校准期间拒绝启动 |
| 06 | 空 | 控制心跳，建议100ms发送；不发ACK以控制9600带宽 |
| 07 | 空 | 人工清错：必要传感器有效且年龄<=20ms、心跳未过期、已停车；只清错，不启动 |
| 08 | 空 | 读取6个参数，回复84，再ACK |
| 81 | 42字节 | 100ms遥测，下面定义 |
| 82 | u8原CMD、u8结果 | 0接受，1拒绝；无自动重试运动命令 |
| 84 | 6个i16 | 按参数ID排列的实际RAM参数 |

STOP示例：`AA 55 01 01 00 02`；心跳：`AA 55 06 00 06`。协议v1与固件版本映射为本交付提交；设备不回传Git哈希，操作者必须记录实际烧录BIN哈希。

## 遥测载荷

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 / 1 | u8 / u8 | 协议版本1 / 实际模式 |
| 2 | u16 | 故障位图 |
| 4 / 5 | u8 / u8 | 低5位黑线位图 / 健康标志 |
| 6 | i16 | 线路偏差，左负右正，-200..200 |
| 8 / 10 | i16 | 左/右编码器速度，按实际窗口归一的counts/10ms |
| 12 / 14 | i16 | 控制器请求PWM千分比，±300封顶；实际驱动还将绝对值<50归零 |
| 16..21 | 3×i16 | 加速度原始XYZ，±2g档，16384 LSB/g |
| 22..27 | 3×i16 | 陀螺原始XYZ，±250°/s档，131 LSB/(°/s) |
| 28..33 | 3×i16 | 校准零偏XYZ；修正值=原始值-零偏 |
| 34 | u32 | 设备毫秒计数，可回绕 |
| 38 / 40 | u16 / u16 | 错帧 / 丢弃TX帧计数低16位 |

健康bit0必要传感器有效、bit1 IMU新鲜、bit2校准完成、bit3校准中、bit4校准失败。IMU初始化成功不代表已有有效样本；读失败或距最新样本>100ms时置无效，数值仅保留历史供诊断。温度在驱动公开接口中可读，v1遥测不含温度。循迹raw可由黑线位图与配置解释，高3位不用于在位检测。

故障bit0心跳、bit1必要传感器/总线、bit2丢线、bit3宽线/分裂线歧义、bit4调度超期、bit5疑似堵转、bit6 UART错误。故障保持锁存；恢复通信/读数不自动清错。清错之后还需新的人工启动。STOP/清错记录处理时间，首字节时间不晚于该边界的START即使跨批次补完也拒绝；同毫秒的新START也保守拒绝，下一毫秒之后重发。

## 控制与边界

上电不自动启动，必要样本与至少一个完整编码器窗口前拒绝启动。TIM6提供5ms采样调度；编码器不足10ms不采样，10..20ms差分按实际时长归一，超过20ms标无效。差分要求每次采样间位移绝对值<32768 counts；CPR1320仅历史暂定，不换算rpm。

速度环10ms位置式PID，P=Kp×误差、I累计Ki×误差、D=Kd×相邻误差变化，输出/积分各限±300，饱和时不提交新积分；零目标清该轮积分/PWM。默认参数`[5,20,5,20,2,0]`为保守软件起点，未经实车调参。循迹转向量`(Kp×偏差+Kd×偏差变化)/100`，左目标=base+turn、右=base-turn，夹在0..20；边缘偏差绝对值>=150时base减半。方向/极性在app_config_f407.h及bsp_f407.h配置，变更需重建并重新台架验证。

所有运动模式在心跳年龄>=500ms的首次检查锁存停车；迟到心跳不能撤销到期故障。软件停车请求不是机械停稳。HAL SPI每事务超时参数2ms、主循环每轮最多处理256 RX字节，检查时间在事务前后推进；这些是软件限制，未测最坏墙钟延迟。CPU卡死/中断全面失效没有独立硬件看门狗保证，需现场风险评估，不能声称500ms硬实时机械停止。

疑似堵转：某轮持续请求绝对PWM>=150而反馈速度为0达500ms即锁存；检测速度为归一整数，低速量化可能误报，错误但非零计数也可漏报。它不测电流或温度，不替代保险丝/电流保护。停止和零目标重置控制状态。共享SPI HAL错误转必要传感器故障；仅IMU身份不符/无新数据且总线无报错时，允许其他诊断和基础控制。MCP初始化失败需修复后复位；回读不是任意电气故障检测器。

校准平均200个有效新样本；每轴陀螺绝对值<=655 raw且加速度模平方落在0.75..1.25 g²范围。阈值内缓慢转动仍可能被吸收为偏置，操作者必须静置。无新样本>100ms或事务失败中止；没有固定总耗时上限。

## 后续赛道策略

首次联调仅接受连续1或2位窄线；全白立即停，宽线/不连续多位均以歧义停车。全黑不能分类为十字或T字。当前交付不宣称实现十字直行/T字可靠识别。

后续候选策略：先记录窄线→宽线的时序、编码器行程和传感器几何；在单独开启且有最大行程/时间的低速探测中，以宽区之后重新出现中心窄线作为“可继续直行”的候选证据，无前向窄线则停车。宽线、十字和T字的观测可能重合，未取得几何/现场数据前不启用此探测。场景需包含直线/S弯、两侧边缘、全白、宽线、分裂线及十字/T字歧义；现有测试证明保守停机，不证明分类成功。限时搜线和短时航向辅助均未启用、未实现运动路径，留待单独标定任务。

现场目标保持原spec：普通线连续3圈、左右急弯/十字直行各10次至少9次成功，分别计数；尚未执行，不以软件模拟替代。
