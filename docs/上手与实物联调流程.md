### 1.2 先认识这些词

| 词 | 在本项目中是什么意思 |
|---|---|
| 核心板 / MCU | 核心板上的 STM32 芯片运行小车程序；电脑负责准备程序和发送控制指令 |
| 固件、编译、下载/烧录 | 固件是 MCU 的程序；编译把源码变成可写入芯片的文件；下载/烧录把它写进芯片内部 Flash |
| 复位、BOOT | 复位相当于让 MCU 重新开始；BOOT 配置决定复位后运行小车程序还是芯片内置下载程序 |
| GND、共地、VCC | GND 是电压参考地；共地是把相关电路地线连通；VCC 是某个器件的供电脚，具体电压要看该模块 |
| GPIO、PA13、PD5 | GPIO 是可编程引脚；PA13 等是芯片信号名，**不是排针第13孔** |
| 排针 / 杜邦线 | 排针是焊在孔中的金属针；杜邦线插头与针或插座配合。只有孔时，线头插进去没有可靠电接触 |
| SWD、ST-Link | SWD 是下载/调试接口；ST-Link 是电脑 USB 与这个接口之间的工具 |
| DFU | 芯片通过 USB 接收固件的下载模式；它不是 U 盘，也不是控制面板使用的串口 |
| UART、TX/RX、COM | UART 是串口；TX 发、RX 收，双方交叉相接；Windows 用 COM 编号表示串口连接 |
| SIM、遥测、心跳 | SIM 是电脑模拟小车；遥测是设备发回的状态；控制心跳是面板持续发送的“仍在控制”消息 |
| PWM、编码器、IMU | PWM 控制电机输出；编码器反馈轮子转动；IMU 测加速度和角速度 |

### 1.3 三条连接路径各做什么

| 用途 | 完整路径 | CubeProgrammer / 面板怎么选 |
|---|---|---|
| 推荐的首次下载 | 电脑 USB → **ST-Link V2** → SWD 信号 → 核心板 | Programmer 选 **ST-LINK**，接口 SWD |
| 备用下载 | 电脑 USB → 核心板 Type-C → 芯片 ROM DFU | Programmer 选 **USB**；须先真正进入 DFU |
| 小车运行时的控制与数据显示 | 电脑蓝牙 → JDY-31 → UART → 核心板 | 面板选蓝牙产生的实际 COM 口 |
| 可选的有线控制 | 电脑 USB → USB 转 TTL → UART → 核心板 | 面板选转换器产生的实际 COM 口 |

**当前固件没有 USB 虚拟串口**仅把核心板 Type-C 接到电脑，不能用它在面板中收小车数据。ST-Link V2 也不作为本流程的串口转换器。

## 2. 操作前的固定约定

1. 接线、焊接、插拔模块前，断开电池、核心板 USB、ST-Link USB 等所有电源。检查结束才重新上电。
2. 裸板下载阶段只用核心板 Type-C 的5V供电，ST-Link 接信号和地；**不接 ST-Link 的3.3V/5V电源输出**。明确标为电压检测输入的脚另见第5.1节。
3. 后续外部5V给核心板供电时，拔掉核心板 Type-C。USB5V与外部5V没有确认隔离前不并供；外部3.3V不接核心板3V3。
4. 传感器检查阶段断开电机动力支路。首次运动时轮子架空，动力开关放在手能立即够到的位置。
5. 只按引脚**功能名**和实际丝印接线。线的颜色、插头能否插进去、商品图方向，都不能单独确定线序。
6. “软件显示停止”“输出 PWM 为零”和“轮子完全停稳”分别观察。当前停车采用高阻滑行，不是立刻抱死。

## 3. 阶段A：把孔、插头和线材准备好

### 3.1 核心板先焊什么

你已确认核心板只有孔。先定位板上的 `DIO`、`CLK`、`GND`，以及后续要用的 PD5、PD6 和各组信号。商品资料标注2.54mm针距；排针行数、孔数、插装方向以实物为准。

- 焊上可可靠连接的排针或适配插座；面包板、转接板、杜邦线需要能配套使用。不要把两侧双排孔想当然地全插入普通面包板。
- 可以先只完成下载所需接口，再完成模块接口；也可以一次焊好，但先检查是否会妨碍安装。
- 固定排针、少量上锡，检查每个焊点是否包住引脚和焊盘，有无相邻焊点连锡。焊接完成后清理并检查再供电；第一次焊接宜请有经验的人复核。
- 万用表的通断/电阻档只在**全断电**时使用。核对同一信号两端是否连通、相邻独立信号是否误短接。电源去耦电容可能造成短暂蜂鸣，不能把一声蜂鸣直接判为短路。

商品图的五孔小接口可见 `BT0、3V3、GND、DIO、CLK`。**BT0 是启动相关标注，不是 NRST/复位。** 不要把别的开发板五针接线顺序搬过来；板上孔位顺序仍须看实物。

### 3.2 先登记缺什么，再配线

| 接口 | 先检查 | 合适的连接方式 |
|---|---|---|
| 核心板与 ST-Link | 两端是否已焊针、信号名称、针距 | 两端都是公针时用母对母；某端为插座则相应改用公头 |
| 核心板与传感器 | 模块是否已焊针；是否为2.54mm | 按端头选公/母杜邦线，做标签；不同针距需对应转接 |
| 循迹板7线口 | 插座型号、间距、1脚和每根线功能 | 匹配线束或转接板；不可只按“7P”选线 |
| 电机6线口 | 电机动力线与编码器线的功能 | 匹配插头与端子，逐根核对；动力线使用足够线径 |
| XY-160D动力与电池 | 接线端子、极性、开关、保险丝 | 可靠端子与粗线；电机电流不走杜邦线或面包板 |
| MCP23S17 | 是裸 DIP28 芯片还是模块，型号是否带 S | 裸芯片需要插座/底板及上拉、去耦；模块须按其板上电路核对 |

MCP23**S**17 是 SPI 器件；MCP23017 是另一种接口，不能直接替换。图纸中的“底板”和自定义线束不会因下载软件自动存在，需要确认是否已经制作。

通过条件：下载接口已可靠焊接，能辨认 DIO/CLK/GND，ST-Link 信号定义已确认。暂时缺传感器线，不阻止先做裸板下载。

### 4.4 不接板，先用 SIM 熟悉面板

已有2026-10-08用户验收证据，本节供重新熟悉和复查；无须把旧验收全部重开。

**2026-10-20进度：用户已完成第4.2至4.4节。** 工具版本截图、第4.3节通过反馈及本次SIM快照/日志核对见第12节；以下步骤保留供后续复查，当前不用重复执行。

```powershell
python -m pip install -r panel/requirements.txt
python -m panel.server --port 8765
```

第二条命令持续运行是正常的，保持终端开着。在浏览器地址栏输入 `http://127.0.0.1:8765`。只开一个控制页面。`make test` 已生成模拟器；若只补建模拟器，可运行 `python tools/build_simulator.py`。

1. 选 **SIM** → “连接”；等“实时”遥测，确认模式“停止”、PWM `0 / 0`。
2. 保持勾选“发送控制心跳”。点“启用低速遥控”，短按方向按钮；松开后目标归零，再点“停止”。也可“启动循迹”后测试停止。
3. 停车时在“停车调参”把基础速度临时从5改为6，点“应用并回读”，确认回读6，再恢复5。若原值不同，先记原值并恢复原值。
4. 点“静止校准”，观察完成；保存参数快照。SIM 的校准只演练操作，不证明真实 IMU 已校准。
5. 每次先启动循迹，再分别注入“丢线”“共享总线故障”“宽线 / 路口歧义”。都应停车、PWM归零且故障锁存。依次“恢复传感器” → “清除故障” → 确认仍停止 → 人工重新启动。
6. **在运动状态**取消“发送控制心跳”，保持页面在前台，等待约1至2秒，应停车且显示心跳超时。恢复心跳不自动清错，清错不自动启动。停车时取消心跳不会新增运动心跳故障。
7. 测试断开重连、切换窗口再回来，均应保持停止；结束点“停止”。终端按 `Ctrl+C` 结束服务。

SIM 的轮速是理想反馈，不模拟电机、无线链路或接线。页面肉眼等待也不能测出精确500ms。

面板“请求PWM”显示**控制器请求的千分比**，不是驱动电平回读。设备计时显示MCU毫秒计数（复位后重新开始，长时间运行会回绕）；线路偏差显示左负右正。这两个读数本次已补到页面。

通过条件：软件测试通过，诊断 BIN 已生成，能使用 SIM 查看状态、停车、清错和保存记录。浏览器打不开时先看终端错误、地址和端口；仅看到服务打印启动地址不算面板已可访问。

## 5. 阶段C：只连裸板，先识别，再下载诊断固件

此时不接电池、电机驱动和其他模块。焊接完成、断电复查通过后再接线。

### 5.1 推荐路线：ST-Link V2 / SWD

ST-Link 的 V2 型号已经确认，但不同外壳/克隆版针序及电源脚定义可能不同。**按你的实物信号名接，不给它套一个通用针号。** ST 官方资料区分 SWD、复位和目标电压检测：[UM1075，§4.2](https://www.st.com/resource/en/user_manual/um1075-stlinkv2-incircuit-debuggerprogrammer-for-stm8-and-stm32-stmicroelectronics.pdf)。

全断电后连接：

| ST-Link 上已确认的信号 | 核心板上已确认的信号 | 说明 |
|---|---|---|
| SWDIO | DIO / PA13 | 下载数据 |
| SWCLK / SWCK | CLK / PA14 | 下载时钟 |
| GND | GND | 共地 |
| VTref / T_VCC，**明确是输入检测脚时** | 核心板3V3 | 只检测目标电压；不能把电源输出当此脚 |
| NRST / RESET，可选 | 板上已确认的 NRST/RST 信号 | 初次可先不接；**绝不接 BT0** |

标为 `3.3V / 5V`、性质未确认的 V2 电源脚先悬空。若工具提示目标电压缺失，核对该 V2 的检测脚定义后再处理，不靠试接电源输出解决。

1. 核心板 Type-C 接电脑供电，ST-Link 自身 USB 也接电脑；此时两者的电源输出没有相连。外部电源保持断开。使用短而可靠的 SWD 线。
2. 打开 CubeProgrammer。选择连接类型 **ST-LINK**，刷新并选择检测到的调试器；接口选 **SWD**，首次时钟可选100或400kHz一类较低档位，以当前软件提供的选项为准。
3. 点击 **Connect/连接**。读到目标芯片信息/存储器信息，才算“连接到核心板”。仅列出了 ST-Link 序列号，表示电脑看到调试器，还不表示它看到了 STM32。
4. 保存连接日志或截图。能识别 STM32F405/407 家族不一定能区分所有料号，以核心板实际芯片标识和512KiB目标配置核对；明显不符先停止。

不能连接时：

| 现象 | 停在这里检查 |
|---|---|
| ST-Link 列表为空 | V2 的 USB 连接、设备管理器状态及 ST-Link 驱动；这还不是核心板固件问题 |
| 能见 V2，但无目标 | 核心板供电、3V3、共地、DIO/CLK是否交叉接错、焊点/线材和电压检测脚 |
| 普通连接仍失败 | 保存日志；可在**确认 NRST 信号且接好**后尝试 Under Reset/复位下连接及低速SWD。不能把 BT0 当复位脚 |
| 提示读保护/保护解除/整片擦除 | 不改变 Option Bytes/保护配置，不自动解除保护；先记录状态，确认处理方式 |

BOOT/DFU 跳线资料不足，不妨碍先走 SWD。若需要恢复正常 Flash 启动，先确认先前自行加的 BOOT0 跳线已按板级连接恢复，不能以未知跳线状态继续猜测。

### 5.2 连接成功后，下载并校验

**首次写入会覆盖芯片当前演示程序。**如需保留原程序且芯片允许读取，应在首次写入前用 Programmer 的读取/保存功能备份内部512KiB Flash（起始 `0x08000000`、长度 `0x80000`）；备份失败时先处理，不通过解除保护强行读取。这里的备份也不包含板载 W25Q16 或 TF 卡内容。

1. 打开 **Erasing & Programming/擦除与编程** 页面，选择：
   `D:\Repository\SmartCar\build\F4-diagnostic\SmartCar.bin`。
2. BIN 的起始地址填 **`0x08000000`**。勾选 **Verify programming/编程后校验**；不要更改 Option Bytes 或保护选项，也不要对 U 盘复制文件。
3. 点击 **Start Programming/开始编程**。等日志明确显示编程成功和校验成功；有一项失败都不算下载通过。按钮英文名称可能随版本略变，按功能对应。[工具功能依据](https://www.st.com/en/development-tools/stm32cubeprog.html)。
4. 断开 Programmer 连接；让板子从内部 Flash 正常启动，按 RST 或重新上电。若调试连接令 MCU 暂停，也要让其恢复运行。
5. 记录 BIN 的完整路径、哈希、下载接口、芯片信息和校验结果。

**下载/校验成功与应用运行成功分开记录。** 当前程序没有板载LED闪烁/蜂鸣器提示；不用“灯没闪”判断失败。裸板没接 MCP/IMU 时，诊断程序可能报告传感器故障，这是尚未接模块的预期状态；真实运行证据要在第6节通过 UART 观察。

### 5.3 另一条路线：用新线观察 USB / DFU

如果只想先试新线，不需要先焊完排针：断开所有模块和外部电源，只把核心板 Type-C 接电脑。

1. Windows 右键开始菜单 → “设备管理器”。观察插拔前后新增/消失的设备。
2. 对该设备右键 → 属性 → 详细信息 → “硬件 ID”，记下 `VID_....&PID_....`；并记录是否出现磁盘、未知USB设备或 DFU 设备。
3. 打开 Programmer，连接类型选 **USB**，点刷新。只有该 USB 下载设备出现并能连接，才继续第5.2节。

| 观察到的现象 | 能得出的结论 / 下一步 |
|---|---|
| U 盘/大容量存储设备，例如历史观察过的 `0483:5720` | 当时运行的是存储设备功能，不能据此当作 ROM DFU；不格式化、不修复、不往盘里复制 BIN |
| `STM32 BOOTLOADER` / `STM Device in DFU Mode`，常见 `0483:DF11` | 符合 ST DFU 枚举；仍需 Programmer 能连接、读出芯片信息再算通过 |
| DFU 有枚举，Programmer 未列出 | 检查当前 Programmer 配套 USB DFU 驱动及设备管理器错误状态；不要给仍为U盘的设备强换DFU驱动 |
| 只有供电灯或完全无新增设备 | 尚不能分清线、电脑USB口、板上模式或连接问题；换电脑直连口、记录新线结果，再查供电 |

STM32F407 的 ROM 下载程序是芯片内置的，不需要先在小车程序中加入 DFU。芯片系统存储器启动条件涉及 BOOT0/BOOT1 在复位时的状态；**商品图不足以确定本板 BT0 的电路与完整操作顺序**。此前排查曾拉高 BT0 并复位/重上电，仍为存储设备，此为2026-10-13历史记录，本次没有复测。没有新资料时不重复猜短接或探接 PB2。[芯片依据：AN2606 Rev70，§34 与启动条件表](https://www.st.com/resource/en/application_note/an2606-stm32-microcontroller-system-memory-boot-mode-stmicroelectronics.pdf)。

通过条件：**SWD 或 DFU 任一路线**完成诊断固件下载和校验，并恢复正常运行；无需两条都通过才进入通信。DFU 未解决时单独记为待查。

<a id="stage-d"></a>

## 6. 阶段D：让面板收到核心板的真实数据

此阶段仍用诊断固件，电机动力断开。先选以下一种通信方式；不要同时把蓝牙和 USB 转 TTL 的 TX 接到核心板 PD6。

| 方式 | 需要什么 | 当前选择依据 |
|---|---|---|
| JDY-31 蓝牙 | 已确认型号的 JDY-31**载板**、电脑蓝牙和 SPP COM 口 | 原修订3方案，不需额外串口转换器 |
| USB 转 TTL，有线可选 | 3.3V逻辑的UART转换器、配套线与Windows驱动 | 蓝牙COM无法建立时可考虑；不是 SWD 下载所必需，也不能用 RS-232 电平设备替代 |

### 6.1 按功能接线

全断电接线。两种方式的核心板端都相同：

| 核心板 | 通信模块 |
|---|---|
| **PD5 = MCU TX，发送** | 模块 **RXD** |
| **PD6 = MCU RX，接收** | 模块 **TXD** |
| GND | GND |

JDY-31 按修订3使用带稳压的载板，VCC给5V；STATE/EN暂不接。先确认你的是这种载板，以及 UART 信号为3.3V逻辑；裸模块不能直接套用载板供电。后续全车时其5V来自降压板；当前核心板 USB 供电阶段，仅在确认板上5V针就是USB5V输出且负载许可时，才从该针给载板取电。**若不能确认，先执行第7.1节建立单一外部逻辑电源，再返回本节**；这一步只检查电源，不先接电机动力。不要临时把两个5V电源并起来。

如果用 USB 转 TTL：核心板仍由 Type-C 供电，转换器接 TX/RX/GND，**VCC不接核心板**；核对其 TX/RX 实际为3.3V逻辑，拨到“3.3V”未必证明所有型号的信号电平会改变。

### 6.2 Windows 连接与面板检查

1. 蓝牙路线先在 Windows“蓝牙和设备”中配对 JDY-31，核对模块名称。配对码按你的模块资料，未知时不把某个常见默认码当作已确认值。
2. 在“设备管理器 → 端口(COM和LPT)”或蓝牙更多设置的 COM 端口页找 SPP 串口；若有入站/出站两个，使用对应模块服务的**出站 COM**。仅“蓝牙已配对”还不等于 COM 可用。USB转TTL则找其驱动枚举的 COM。
3. 按第4.4节启动面板。刷新端口列表，选实际 COM，不能继续选 SIM。仓库当前协议固定为 **9600、8N1**，面板后端已按此设置。
4. “连接”后会自动发停止并读参数；等状态变为“实时”，观察设备毫秒数持续增长、模式“停止”、PWM `0 / 0`。ACK/“命令接受”只说明命令处理结果，实际模式以遥测为准。
5. 裸板缺传感器时故障不为零，面板会把启动按钮置灰，记录该现象即可；**这不能单独证明固件拒绝机制**。第8节传感器就绪、故障清除后，再验证诊断固件仍拒绝“启用低速遥控”和“启动循迹”，不为启动成功提前换运动固件。

只有 SIM：检查 pyserial、COM 驱动/蓝牙SPP及刷新。真实 COM 无数据：核对交叉线、共地、波特率、MCU是否从Flash运行、是否占用了另一个程序的串口；500ms无有效遥测时面板会标过期并禁止启动。

通过条件：选的是实际COM，设备计时持续更新、模式保持停止、有日志。**本阶段通过后**才把“应用运行/真实通信”记为通过；诊断固件的主动拒绝验证留到传感器就绪后。

<a id="stage-e"></a>

## 7. 阶段E：先建立逻辑电源，再接传感器

### 7.1 电源怎么分配

以下来自修订3设计，仍需核对你手上的实际模块。电压档测量时黑表笔接GND、红表笔接被测点；表笔插在COM/V电压测量孔，不能用电流档跨接电源。

| 支路 | 修订3接法 | 上电前必须核对 |
|---|---|---|
| 电池主支路 | 3S电池，标称11.1V、满电12.6V → 保险丝 → 总开关 → 分为动力和降压输入 | 电池能力、极性、线径和保护；图纸建议持续≥10A/短时≥15A，保险丝5A慢断只是初选，需按实测电流核验 |
| 核心板 | 降压板5V → 核心板5V，GND共地 | 外部5V供电前拔核心板USB；不用外部3.3V并联核心板稳压器 |
| MPU6500、JDY-31 | 图示**带稳压模块/载板**的VCC用5V | 核实模块版本与稳压输出；信号仍为3.3V，裸芯片不接5V |
| 编码器、循迹板、MCP23S17 | 外部3.3V | 核对各模块实际允许供电和输出电平，不因循迹板丝印“5V”就直接改供5V |
| 电机动力 | 电池经保护、开关直接到XY动力端 | 此阶段保持物理断开；不走降压板Vout=Vin、面包板或杜邦线 |
| 所有地线 | XY动力PGND/控制GND、降压输入地、核心板、传感器、蓝牙共地 | 动力回流不经过细信号地线；按底板合理汇接 |

图纸要求 XY 供电旁路470至1000μF/35V，注意电解电容正负；两电机端各100nF去干扰。实际电源板有不同版本，旧资料的5V/3.3V额定能力不能跨版本套用。

操作顺序：**不接负载先测降压输出5V/3.3V → 全断电 → 逐组接入负载 → 上逻辑电源复测**。留意压降、异常发热和复位，发现异常立即断电检查。上外部5V后仍可用 ST-Link 下载，但其电源输出继续不接，核心板Type-C拔掉。

### 7.2 MCP23S17：循迹接口的必要部分

循环检测的五路输出通过 MCP23S17 接入，不能跳过它直接沿用旧 F103 的 PB5至PB9。若手上是已制作好的底板，先检查其线路是否与下表一致；若是裸芯片，需要实际制作这些连接。

**仅针对 MCP23S17-E/SP、DIP28 封装**：从芯片顶面看，缺口向上，左上1脚，沿左侧向下至14，右下15、向上至右上28；先核对定位标记再上电。其他封装不可照此针号。

| 核心板/电源 | MCP23S17 信号与DIP28脚号 |
|---|---|
| PB13 | SCK，12 |
| PB15 | SI/MOSI，13 |
| PB14 | SO/MISO，14 |
| PE7 | /CS，11；另经10kΩ上拉到3.3V |
| 3.3V / GND | VDD，9 / VSS，10；两脚旁就近100nF去耦 |
| GND | A0/A1/A2，15/16/17 |
| 3.3V经10kΩ | /RESET，18 |
| 循迹OUT1至OUT5 | GPA0至GPA4，21至25；每路各10kΩ上拉到3.3V |
| 不接外线 | INTB/INTA，19/20；GPB0至7，1至8；GPA5至7，26至28 |

未用端口由软件配置输入上拉；GPA7不作插拔检测。MCP与IMU共用下面的PB13/14/15，但各自 /CS 独立。核心板还带 W25Q16/TF 等器件，商品图未给完整占用表；若发现同名引脚已有连接/争用，先核对，不强行并接或拆焊。

### 7.3 MPU6500：共用 SPI 的另一模块

| 核心板 | 图示MPU6500模块丝印 |
|---|---|
| PB13 | SCL / SCLK（SPI时钟） |
| PB15 | SDA / SDI（SPI数据输入） |
| PB14 | AD0 / SDO（SPI数据输出） |
| PB12 | NCS，另10kΩ上拉到3.3V |
| PB10 | INT |
| 5V | 带稳压模块的VCC；先核实模块内部稳压输出约3.3V |
| GND | GND、FSYNC |
| 不接 | EDA、ECL |

SCL/SDA 在这个模块上复用为 SPI，不是让你同时另接一套 I²C。当前软件使用硬件SPI2、Mode0，频率约656.25kHz；首次接线不需要在 CubeMX 中重新配置。

### 7.4 五路循迹板与自定义7线接口

| 本方案自定义 J_LINE 脚号 | 功能 | 去向 |
|---|---|---|
| 1 | VCC | 外部3.3V |
| 2 | GND | 共地 |
| 3至7 | OUT1至OUT5 | MCP GPA0至GPA4 |

**这不是循迹板原厂7P插头的物理顺序。**必须按实物确认并做1脚标记；不能用表格从左到右直接插原插头。每路输出在确认信号前应测到高≥2.64V、低≤0.66V；黑线通常为低，仍按实测核对。

通过条件：逻辑电源正常、焊接与接口线序明确，MCP/IMU/循迹板各组接线检查完成。电机动力仍断开，继续第8节检查真实数据。

## 8. 阶段F：诊断固件下逐个检查真实传感器

### 8.1 先看通信与健康状态

保持实际 COM 和实时遥测。接好模块后复位，再观察必要传感器故障能否在条件恢复后人工清除。**MCP初始化失败后，必须修复接线并复位**；“清除故障”不能代替重新初始化。

软件的“必要样本有效”表示 MCP 读写及编码器采样窗口等内部条件满足，**不能证明编码器物理接好，也不能证明循迹板在位**。拔掉循迹板与全白可能得到相同输入，必须做下面的实物动作验证。

IMU身份不匹配或无新数据而SPI事务未报错时，软件仍允许其他诊断与基础控制；共享总线/IMU事务错误会引发必要传感器故障。不要把“软件允许启动”当作整车检查已完成。

### 8.2 五路循迹

1. 固定安装高度，在相同照明下，逐个传感器移到白底、黑线上，记录每一路变化；必要时调整模块阈值。
2. 面板位图应为**黑线=1，bit0对应车体最左侧**。逐路验证，而不是只看“有数”。
3. 让窄线从左到右移动，面板“线路偏差”应由负变正。诊断固件下只核对位图与偏差，不要求出现丢线/歧义故障；进入运动固件的循迹模式后，全白才会触发丢线停车，三路及以上或不连续多路会触发歧义停车。
4. 保存高度、间距、线宽和极性。若方向/极性相反，先停车断电核对线序；确需修改配置时改 `Core/Inc/app_config_f407.h`，重建并重做对应检查。

### 8.3 IMU

1. 把车固定不动，确认显示数据持续更新、IMU新鲜；当前±2g档下，加速度合量应大致对应1g（约16384原始单位），不要求某一轴永远等于1g。
2. 轻缓改变模块朝向，观察对应加速度/角速度变化，再放回静止状态。
3. 停车且IMU有有效数据时点“静止校准”，全过程静置；程序平均200个有效新样本，无固定的必然完成秒数。校准成功后保存快照与零偏。
4. 数据陈旧/读取失败或晃动会导致校准失败；查供电、NCS、SPI、INT和安装，不能靠反复点启动掩盖故障。

当前不输出可靠的绝对航向，IMU也尚未用于运动中的航向辅助。

### 8.4 编码器：只手转，不通电机动力

| 编码器功能 | 左电机 | 右电机 |
|---|---|---|
| A | PC6 | PD12 |
| B | PC7 | PD13 |
| VCC / GND | 外部3.3V / 共地 | 外部3.3V / 共地 |

修订3原电机线束为：蓝5=编码器电源、黑2=GND、黄3=A、绿4=B；**仅在确认是该线束后**使用颜色辅助。红1/白6是电机动力端，白线不是地，蓝线不能接12V。

分别手转两轮：只应对应轮有计数/速度变化，按车体前进方向转时应为正，反向应为负。面板速度是 **counts/10ms（每10毫秒归一的计数）**，手转停下后回零；不能据此套未测的1320 counts/圈换算转速。

每圈计数CPR仍需实测。当前面板显示窗口速度，**没有累计圈计数功能**，不能把多行窗口数直接当作一圈总数；需要记录完整采样时间并积分，或另加累计计数诊断后再标定。

通过条件：五路位置/黑白/偏差方向正确，IMU读取与静置校准有记录，手转编码器左右通道和正负正确。任何一项未完成都记为未测，不把必要样本健康标志代替这些检查。

传感器就绪、故障已清且心跳正常后，诊断固件下试点“启用低速遥控”和“启动循迹”，应收到拒绝并保持停止。此时仍不接电机动力。

## 9. 阶段G：电机接线、架空测试、停车验证

### 9.1 XY-160D先解决电气兼容性

修订3要求本款 XY 的信号“+5V”参考端可用核心板3V3，并在 IN1至4各加10kΩ上拉到核心板3V3、移除原两路PWM下拉。**这是一项待核验的硬件条件，不是所有XY-160D通用事实。**仅凭核心板型号确认，不能确认电机驱动版本兼容。

在确认你这版参考供电允许3.3V、所需控制高≥3.0V/低≤0.8V、每脚灌电流≤8mA，以及电阻连接方案前，**不接动力、不直接改接5V信号，也不照图盲目拆电阻**。请用该驱动板资料/实物检查落实；必要时另行设计电平转换。

### 9.2 断电接好控制与动力

| 核心板 | XY-160D |
|---|---|
| PE9 | ENA1 / ENA，左PWM |
| PE10 / PE8 | IN1 / IN2，左方向 |
| PE11 | ENA2 / ENB，右PWM |
| PE12 / PE13 | IN3 / IN4，右方向 |
| 核心板3V3 | **已确认兼容后的**信号参考“+5V” |
| GND | 控制GND；与动力PGND共同接地 |
| 电池保护/保险丝/总开关后的动力正、负 | 驱动电源+、PGND |
| 左电机红1/白6；右电机红1/白6 | OUT1/OUT2；OUT3/OUT4（仍先确认线束） |

动力先保持断开，只上逻辑电源，检查启动/复位时方向为 `11`、PWM为零；有示波器再测2kHz与启动/换向波形。万用表只能帮助看静态电平，不能替代这些波形检查。上电到软件执行前的电平还依赖外部电阻，不能只靠固件保证。

### 9.3 条件满足后，换运动固件

1. 第8节和XY兼容性通过后，全断电，确保轮子架空。保持动力断开，按第5节另行下载 `build/F4/SmartCar.bin` 并校验，记录新的哈希。
2. 恢复正常启动，面板连接真实COM。确认实时、停止、PWM零；恢复必要样本和心跳，若有故障先查清并按第10节清错。
3. 全断电接回动力，重新检查极性和固定；上电后仍应停止。不满足立即断开动力。
4. 勾选“发送控制心跳”，点“启用低速遥控”。先短按单轮转向按钮再松开，分别确认左右通道和方向；再短按前进/后退。手和导线远离轮子。
5. 松开按钮时目标归零；再点红色“停止”，确认模式停止、PWM零，记录轮子实际滑停时间。

面板按钮下发的是约±5 counts/10ms目标，**不是5%占空比，也不是已标定的低速**。当前控制器输出封顶30%，驱动小于5%归零；面板没有直接PWM滑杆。若方向错误、明显振荡、轮子不转或故障，不持续加大指令，更不要手捏转动轮子制造负载。

电机方向配置在 `bsp_f407.h`；编码器方向配置在 `app_config_f407.h`。按实际观察决定改哪个，重建、下载并重新验证，不能一口气同时翻转多个配置来掩盖问题。

### 9.4 架空验证停止与失联

先正常短时运行，再分别测试松开方向键、点“停止”、面板切走、断开通信和运动中取消心跳。每次观察面板请求PWM归零、轮子滑停，确认开关能及时切断动力。**面板请求为零不证明实际引脚波形已归零**；万用表只能辅助检查最终静态电平，精确输出延迟/脉冲需示波器等仪器，无相应仪器就在记录中填“电气时序未测”。机械滑停可记录肉眼现象，粗略计时要注明方法，不能冒充精密测量。

运动状态心跳年龄达到500ms后，程序在首次检查时锁存停车；恢复心跳、清除故障都不自动重启。**500ms是软件超时阈值，不是机械停车时间或最坏延迟承诺**。CPU卡死等情况没有独立硬件看门狗兜底，不能仅依赖网页停止按钮。

疑似堵转检测基于“持续请求PWM且零计数”，不测电流/温度。不要故意长时间堵转试保护；保险丝、电流限制和温升仍须独立检查。

## 10. 阶段H：低速落地、调参和故障恢复

### 10.1 每次故障都按同一顺序恢复

**先停机/必要时断动力 → 排除实物问题 → 恢复新鲜数据与心跳 → 清除故障 → 确认仍停止且故障无 → 再人工启动。**

| 故障/现象 | 优先检查 |
|---|---|
| 心跳超时 | 页面是否在前台、心跳勾选、COM/蓝牙连接；恢复通信后仍要人工清错 |
| 传感器失效 | 电源、MCP接线/地址/复位/片选、共享SPI；MCP初始化失败修好后复位 |
| 丢线 / 线路歧义 | 传感器高度、黑白阈值、线宽、位图与线序；拔线和全白不能自动区分 |
| 调度超期 / UART错误 | 保留日志，检查供电干扰与通信，再定位；不反复启动 |
| 疑似堵转 | 断动力后检查卡住、编码器掉线、方向反馈错误；低速计数量化也可能误报 |
| 模式启动拒绝 | 是否仍为诊断固件、故障未清、必要样本过期、心跳缺失或校准中 |

### 10.2 首次落地只跑简单窄线

架空各项通过、无异常发热/复位，停车能力有记录后，准备可立即断电的空旷场地。从直线、缓弯、连续窄线开始，先低目标速度遥控，再循迹。首次软件只接受1位或相邻2位黑线：全白停车，宽线/分裂线/十字或T字造成的歧义停车。

**当前没有十字/T字可靠识别、自动搜线或航向辅助。**不能将“过路口停车”当作参数没调好而盲目加速。后续目标是普通线连续3圈、左右急弯及十字直行分别10次至少9次成功；这些仍需独立实现/现场验收。

### 10.3 调参的起点和保存

| 参数 | 源码默认值 | 单位/含义 |
|---|---:|---|
| 基础速度 | 5 | counts/10ms；允许0至20 |
| 循迹 Kp / Kd | 20 / 5 | 外环转向响应，允许0至200 |
| 速度 Kp / Ki / Kd | 20 / 2 / 0 | 速度闭环，允许0至200 |

这些是软件起点，未经实车标定。先完成方向/反馈检查，再在停车时一次只改一个参数、回读确认，架空观察速度环，再低速落地观察循迹。不要抄历史F103的PID数值；当前速度环是位置式PID。

参数仅存在RAM，复位后恢复源码默认值。每次改变都“保存参数快照”，另记跑道和结果；稳定后再决定是否写回 `Core/Inc/app_config_f407.h` 的默认值并重新构建。2026-10-07旧快照的基础速度4只是当次记录，不覆盖当前默认5。
