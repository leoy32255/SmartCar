# Windows控制面板

实现位于panel/。这是本机浏览器界面与Python串口后端，不依赖云服务。默认SIM，真实蓝牙使用Windows配对产生的SPP COM口。Mac保留Python/浏览器可移植性，本轮未验证。

## 启动

在仓库根目录使用Python3和本机GCC：

```powershell
python -m pip install -r panel/requirements.txt
python tools/build_simulator.py
python -m panel.server --port 8765
```

HOST_CC可指定GCC路径（见F407最小构建）；SIM需要先生成build/host/smartcar_sim.dll。实际COM仅需要pyserial，不依赖模拟器。打开`http://127.0.0.1:8765`，单个浏览器标签使用；不要同时打开多个控制页面。后端仅绑定127.0.0.1，不向局域网开放。停止服务用终端Ctrl+C；本任务未连接真实COM。

1. 首先选择SIM并连接；连接会发STOP并请求参数，等待实时遥测。
2. 启动循迹或启用低速遥控。遥控按钮按住发送±5 counts/10ms或单轮0/5，松开归零；固件最多接受±10。请勿据此解释为已标定物理低速。
3. 红色停止按钮发STOP；界面以设备遥测显示实际模式，ACK只说明接受/拒绝。
4. 仅停车时调参；应用后请求实际值回读。静止校准需有效IMU样本。
5. SIM可以注入丢线、总线失败、宽线歧义。先恢复传感器，再人工清错，最后重新启动。关闭“发送控制心跳”可验证500ms锁存停车。
6. 断开/重连保持停止。切出页面、隐藏或关闭会尝试STOP并停止页面心跳；网络请求失败时仍依赖固件心跳超时。不要把浏览器发出STOP视为机械已停。

浏览器每100ms请求一次心跳和状态，后端不自行持续发心跳。模拟器复用Core/F407/control.c和runtime.c；轮速为理想目标反馈，不模拟电机、传感器电气或无线链路。控制器与真实App测试另有独立覆盖。

## 日志和参数

每次连接自动建立`logs/日期-时间-微秒.jsonl`；每行一个UTF-8 JSON对象，包含UTC time与kind。connect记协议/固件系列及端口，command记命令字和十六进制载荷，rx记原始帧载荷，telemetry记模式/故障/五路/编码器/IMU原始及零偏，parameters记六项实际参数，disconnect记结束。日志自动flush，目录被gitignore忽略；写入失败显示错误并停止本地发送。日志会话头不证明实际烧录版本，须在课堂表另记BIN哈希。

“保存参数快照”下载JSON（含当前遥测、参数、端口、日志路径与时间）。设备参数仅在RAM，复位恢复app_config_f407.h默认值。将已验证参数抄入课堂模板，确认后再改源码默认；不要把未验证值标为标定结果。

## 排错

- SIM加载失败：先运行build_simulator.py，检查HOST_CC/平台位数；不要把缺库当串口故障。
- 端口列表只有SIM：检查pyserial安装、Windows配对与SPP枚举；刷新列表。未枚举不是固件协议结论。
- 命令拒绝：查看故障、样本新鲜度、当前模式、参数范围；先停车/恢复条件/清错，再人工启动。诊断固件永远拒绝运动模式。
- 无遥测/数据显示过期：面板500ms无有效遥测标过期并禁止启动；检查COM、9600/8N1、帧版本。切勿盲目反复启动。
