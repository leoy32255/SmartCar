# 移植到 STM32F407VET6

> 本工程在架构上已经为这次升级做了准备：**业务代码（motor / encoder / imu /
> track / pid / control / comm / app）一行都不用改**，
> 需要动的只有 `bsp_config.h` / `bsp_config.c` 这两个文件里的 MCU 分支，
> 以及构建配置。
>
> 本文档说明已完成的部分、你还需要做的部分，以及换板后值得顺手做的升级。

## 〇、目标板说明：STM32F407VET6 核心板（Type-C 口）

按实际选的这块核心板的参数：

| 项目 | 参数 | 对本工程的影响 |
|---|---|---|
| 主控 | STM32F407VET6（Cortex-M4，168MHz） | 内存/引脚都远超需求，**可以上 FreeRTOS** |
| Flash / SRAM | 512KB / 192KB | 现在约 20KB Flash / 4KB RAM，非常宽裕 |
| **高速晶振** | **板载 8MHz** | ✅ **与我写的 F4 时钟配置完全match**（PLLM=8/PLLN=336/PLLP=2） |
| 低频晶振 | 板载 32.768kHz | 供 RTC 用，本工程不用；注意 PC14/PC15 被它占用 |
| 供电 | **Type-C 外部 5V 供电**，板载 3.3V 稳压 | ✅ 电源模块的 5V 直接进 Type-C 即可 |
| 下载方式 | **Type-C DFU 下载** + SWD 调试口 | 可以不买 ST-Link，见下文 |
| IO | 顶部 2.54mm 排针，**全 IO 引出**（22×2P 两组） | 引脚不再紧张，可做的升级见第六节 |
| 板载外设 | W25Q16（2MB Flash）、SD/TF 卡槽、OLED/TFT 接口、**用户按键**、程控 LED | ⚠️ 有 SPI 冲突风险，见下文注意事项 |

### 关于这块板的三个提醒

**1. 板载 W25Q16 和 SD 卡槽也走 SPI —— 接线前先确认它们占哪个 SPI**

`W25Q16` 和 `SD/TF` 卡槽都需要 SPI 总线。如果它们固定接在 SPI1 或 SPI2 上，
而你又想用它接 IMU，就会冲突。

**处理办法**：拿万用表在板子背面顺着走线量一下，或者找卖家要原理图。
在此之前**先用软件 SPI 接 IMU（现在的代码就是软件 SPI，可以原样用）**，
确认 W25Q16 占的总线后再决定是否改用硬件 SPI。

> 好消息：本工程 IMU 用的是软件 SPI，接在任意 4 个空闲 GPIO 上，
> 所以即使板载 Flash 占用了 SPI1/SPI2，也不影响现在的代码直接跑。

**2. 可以用 Type-C DFU 下载，不一定要 ST-Link**

这块板支持 Type-C DFU 下载（注意：**是 DFU 不是串口**）。
好处是不用额外买调试器；代价是不能单步调试。

如果要用 DFU，需要在 CubeMX 里把 `USB_OTG_FS` 配成
`Device (FS)` + `DFU` 类，然后生成的固件通过 STM32CubeProgrammer
的 USB 模式烧录。**SWD 排针仍然保留**，想调试就插 ST-Link。

**建议**：先按 SWD + ST-Link 走（本文档默认路径，Makefile 的
`flash` / `flash-ocd` 都是这条路），等跑通了再研究 DFU。

**3. 板载用户按键可以用来做"启动/急停"**

现在代码上电后是**停机**状态，必须靠蓝牙下发指令才动作。
在还没有手机 App 的阶段，这会让台架调试很麻烦。

两个解决办法：

- **临时**：把 `bsp_config.h` 里的 `APP_AUTOSTART_MODE` 改成 `1`，
  上电校准完直接进循迹模式（调完记得改回 0）
- **长期**：用这块板的**用户按键**做启动/停止/校准，
  这样脱离上位机也能完整操作。按键引脚需要你从板子丝印或原理图确认，
  然后按 `led.c` 的模式加一个 `button.c` 即可。
  注意按键要做消抖（20ms 左右的软件延时判断）并优先用 EXTI 中断。

## 一、为什么这次移植成本很低

两个系列之间**真正不同**的只有三件事，都已经隔离在 `bsp_config.*` 里：

| 差异点 | F103C8T6 | F407VET6 | 已在代码中处理 |
|---|---|---|---|
| 时钟树 | PLL 单一倍频系数 ×9 | PLL 是 M/N/P/Q 四参数 + 调压器 + 过驱动 | ✅ `Bsp_Clock_Config()` 双分支 |
| GPIO 复用模型 | AFIO 重映射，`GPIO_InitTypeDef` 无 `Alternate` 字段 | 必须显式指定 `GPIO_AFx_xxx` | ✅ `gpio_af_pp(pin, af)` + `BSP_AF_*` 宏 |
| EXTI 时钟 | `__HAL_RCC_AFIO_CLK_ENABLE()` | `__HAL_RCC_SYSCFG_CLK_ENABLE()` | ✅ `BSP_EXTI_CLK_ENABLE()` 宏 |

其余的 HAL 接口在两个系列上**完全一致**：
`HAL_TIM_PWM_Init` / `HAL_TIM_Encoder_Init` / `HAL_UART_Init` / `HAL_GPIO_Init`
以及 `TIM_HandleTypeDef` / `UART_HandleTypeDef` 的字段都是同一套。

## 二、引脚几乎 1:1 平移

好消息：主要外设在 F407VET6 上的默认复用位置**和 F103 完全相同**。

| 功能 | F103C8T6 | F407VET6 | 是否要改 |
|---|---|---|---|
| TIM1_CH1 / CH2（PWM） | PA8 / PA9 | PA8 / PA9 | ✅ 相同 |
| TIM2_CH1 / CH2（左编码器） | PA0 / PA1 | PA0 / PA1 | ✅ 相同 |
| TIM3_CH1 / CH2（右编码器） | PA6 / PA7 | PA6 / PA7 | ✅ 相同 |
| USART2_TX / RX（蓝牙） | PA2 / PA3 | PA2 / PA3 | ✅ 相同 |
| 软件 SPI IMU | PA4/PA5/PA11/PA12 | 同左（纯 GPIO） | ✅ 相同 |
| 循迹 5 路 | PB5~PB9 | PB5~PB9 | ✅ 相同 |
| 电机方向 | PB12~PB15 | PB12~PB15 | ✅ 相同 |
| TB6612 STBY | PB1 | PB1 | ✅ 相同 |
| 蜂鸣器 / LED | PB10 / PC13 | PB10 / PC13 | ✅ 相同 |

**结论：`bsp_config.h` 里的引脚宏一个都不用改**，
只需要补充 F4 的 AF 编号（已经写好了）。

> 注意 LQFP100 封装上 USART2 还有 PD5/PD6 等可选位置，
> 但 PA2/PA3 依然可用，我们保持原样。

## 三、你还需要做的步骤

### 步骤 1：为 F407VET6 生成 HAL 库与启动文件

用 CubeMX 新建工程（芯片选 `STM32F407VETx`）：

| 项目 | 设置 |
|---|---|
| RCC → HSE | Crystal/Ceramic Resonator |
| SYS → Debug | Serial Wire |
| SYS → Timebase | SysTick |
| Clock Configuration | HSE 8MHz → PLLM=8, PLLN=336, PLLP=2, PLLQ=7 → **168MHz**<br>AHB /1 = 168，APB1 /4 = 42，APB2 /2 = 84 |
| Toolchain | Makefile |

生成的这些文件拷进本工程（**保留 F103 的版本，或换成 F4 的，两者不共存**）：

```
Drivers/STM32F4xx_HAL_Driver/
Drivers/CMSIS/Device/ST/STM32F4xx/
Core/Startup/startup_stm32f407xx.s
STM32F407VETx_FLASH.ld
Core/Inc/stm32f4xx_hal_conf.h
```

### 步骤 2：同样删掉 CubeMX 生成的中断函数

和 F103 一样，`stm32f4xx_it.c` 里不要有
`SysTick_Handler` / `EXTI0_IRQHandler` / `USART2_IRQHandler`，
删掉 `main.c`（本工程自带）。
详见 [CubeMX配置说明.md](CubeMX配置说明.md) 第三节。

### 步骤 3：切换编译目标

```bash
make clean
make MCU_FAMILY=F4 -j8
```

或者在 VS Code 里用 **`Build (F407VET6)`** 任务（`.vscode/tasks.json` 已配好）。

`Makefile` 会自动切换：
- `-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard`（启用硬件浮点）
- `-DSTM32F407xx`
- HAL 库目录改为 `STM32F4xx_HAL_Driver`
- 启动文件与链接脚本

`bsp_config.h` 里的 `#elif defined(STM32F407xx)` 分支会自动生效，
不需要手改任何宏。

### 步骤 4：确认 `stm32f4xx_hal_conf.h` 打开的模块

```c
#define HAL_MODULE_ENABLED
#define HAL_GPIO_MODULE_ENABLED
#define HAL_RCC_MODULE_ENABLED
#define HAL_CORTEX_MODULE_ENABLED
#define HAL_TIM_MODULE_ENABLED
#define HAL_UART_MODULE_ENABLED
#define HAL_FLASH_MODULE_ENABLED
#define HAL_EXTI_MODULE_ENABLED
#define HAL_PWR_MODULE_ENABLED      // 过驱动 EnableOverDrive 需要
```

## 四、移植时最容易踩的三个坑

### 坑 1：编码器必须配 AF，否则速度恒为 0

F1 上编码器引脚配"浮空输入"就能工作，F4 上**必须在 `GPIO_InitTypeDef`
里指定 `Alternate = GPIO_AF1_TIM2`**，否则定时器根本收不到脉冲。

现象：电机正常转，但 `Encoder_GetSpeed()` 一直是 0，
速度环以为车没动，PWM 一路顶到限幅。

代码里已经用 `#if BSP_GPIO_HAS_AF` 处理了。
如果你自己加了编码器或改了引脚，**记得同步加 AF 配置**。

### 坑 2：USART2 的 RX 也要配成 AF 模式

F1 上 `PA3` 配成浮空输入就能收数据；F4 上 RX 同样要 `GPIO_AF7_USART2`。
已经处理，但改串口引脚时要注意。

### 坑 3：FPU 没使能 → 一进 main 就 HardFault

F4 用 `-mfloat-abi=hard` 编译时，普通 float 运算会编成 FPU 指令。
如果 CP10/CP11 没使能，第一条浮点指令就 HardFault。

`Bsp_Clock_Config()` 的 F4 分支里已经显式使能了：
```c
SCB->CPACR |= ((3UL << (10U * 2U)) | (3UL << (11U * 2U)));
```

另外**不要删掉启动文件里对 `SystemInit()` 的调用**，它也会做这件事。

## 五、需要注意的参数变化

### 1. PWM 频率会自动保持 20kHz

F4 的 TIM1 时钟是 168MHz（APB2 84MHz × 2），
不是 F1 的 72MHz。`Bsp_Pwm_Init()` 里 ARR 由
`BSP_TIM1_CLK_HZ / MOTOR_PWM_FREQ_HZ - 1` 算出：

| MCU | TIM1 时钟 | ARR | 实际 PWM |
|---|---|---|---|
| F103 | 72 MHz | 3599 | 20.00 kHz |
| F407 | 168 MHz | 8399 | 20.00 kHz |

如果这里写死 3599，F4 上会变成 46.7kHz，TB6612 开关损耗上升、发热增加。

### 2. `ENCODER_CPR` 不需要改

编码器是机械计数，与 MCU 主频无关。
仍然是 `11 × 30 × 4 = 1320` counts/圈。

`SPEED_WINDOW_MS` 也保持不变。F4 主频更高，如果想让速度反馈更细腻，
可以把 `CTRL_PERIOD_MS` 从 5 降到 2（500Hz 控制环）。

### 3. 定时器位宽（已处理，但要知道）

F407 上 **TIM2 和 TIM5 是 32 位**，TIM3/TIM4 是 16 位。
`encoder.c` 按 16 位处理回绕（读 `(uint16_t)CNT` + 有符号差值），
而 `Bsp_Encoder_Timer_Init()` 把 `Period` 设为 `0xFFFF`，
所以 TIM2 依然按 16 位回绕，行为与 F103 完全一致。

**不要**把 `Period` 改成 `0xFFFFFFFF` 之后又保留 16 位截断逻辑 ——
虽然在本项目的速度范围内实际不会出错，但会让人误解代码意图。

### 4. 姿态解算会明显变快

F4 有单精度硬件 FPU，`filter.c` 里的 `atan2f` / `sqrtf`
从软件库调用变成硬件指令，加上 168MHz 主频，
单次 `Filter_Update()` 从 F1 上的约 20μs 降到 2μs 以内。
这给"提高控制频率"或"上更复杂的滤波（二阶互补 / 卡尔曼）"留出了空间。

## 六、换板后值得顺手做的升级

F407VET6 是 LQFP100，比 LQFP48 多出大量引脚，
之前被引脚数限制而妥协的地方都可以改善：

### 1. IMU 改回硬件 SPI（推荐，最明显的提升）

现在软件 SPI 是为了避开 F103 的引脚冲突。
F4 上可以把 SPI1 配到 **PB3(SCK) / PB4(MISO) / PB5(MOSI)，AF5**，
硬件 SPI 跑到 10MHz，14 字节读取从 ~40μs 降到 ~15μs。

需要改的只有 `imu.c` 里的 `spi_transfer()` / `mpu_read_reg()` 等底层函数，
上层 `Imu_ReadData()` 和姿态解算完全不用动。

### 2. 加电池电压监测（强烈推荐，优先级最高）

目前代码没法知道电池电量，3S 锂电过放会永久损坏。
F4 上有富余的 ADC 引脚，用 `PC0`(ADC123_IN10) 经分压电阻
接电池正极，就能实时回传电压并在低压时报警/停车。

> 3S 锂电放电到单节 3.0V（整组 9.0V）以下就会开始不可逆损伤，
> 建议在 10.5V 报警、10.0V 强制停车。
> 分压电阻用 10kΩ + 3.3kΩ 左右，把 12.6V 分到 3.1V 以内再进 ADC。

### 3. 加一路独立调试串口

现在蓝牙和调试共用 USART2，调 PID 时看不到日志。
F4 可以把 `USART1`(PA9/PA10) 或 `USART3`(PB10/PB11) 空出来
专门接 USB-TTL，和蓝牙互不干扰。

> 注意：若用 USART1 的 PA9/PA10，会和 TIM1_CH2 的 PA9 冲突，
> 建议用 USART3(PB10/PB11)，但 PB10 现在是蜂鸣器 —— 挪一下蜂鸣器即可。

### 4. 加一块 OLED 显示状态（这块板已留好接口）

核心板有 OLED/TFT 通用接口，支持 0.96 寸 OLED。
现在调 PID 只能靠蓝牙回传看数据，非常不方便。
加一块 OLED 把偏差 / 双轮速度 / PID 参数直接显示出来，
调参效率会有质的提升（改一个参数立刻看到效果，不用切手机）。

代码上只需要加一个 `oled.c`，在 `app.c` 的控制任务里
每 100ms 刷新一次即可。

### 5. 用 TIM4 加第三、四路编码器

如果以后改成四轮驱动，`TIM4_CH1/CH2` = PB6/PB7 可以做第三路编码器。
（现在 PB6/PB7 是循迹 OUT2/OUT3，需要重新分配。）

### 6. 迁移到 FreeRTOS

F407VET6 有 **192KB SRAM + 512KB Flash**（还有 64KB CCM RAM 可单独放栈），
跑 FreeRTOS 完全没有资源压力。
可以把控制、通信、姿态解算、显示拆成独立任务，
用队列传递数据，代码结构会更清晰。

不过要注意两点：

- **控制任务的实时性要求不会因为上了 RTOS 就降低**。
  控制周期仍然要靠定时器中断 + 任务通知严格保证，
  不要依赖 `vTaskDelay` 的精度（它受 tick 频率和调度影响）。
- F1 上不上 RTOS 的原因（20KB RAM 太紧）在这里不成立了，
  但**也没有必须上的理由** —— 现在的两层调度（1ms SysTick 分频 + 主循环）
  已经能满足需求。建议先跑通现有结构，确有需要再迁，
  不要为了用 RTOS 而用。

### 8. 用板载 W25Q16 / SD 卡做数据记录

调 PID 时最缺的是"这一趟到底发生了什么"。
板载 2MB Flash 或插一张 TF 卡，把每个控制周期的
偏差 / 双轮目标速度 / 实际速度 / PWM 记下来，
跑完导出来画曲线，比盯着串口数字猜有效得多。

> **优先级建议**：先做第 2 条（电池电压监测，唯一一个不做可能烧硬件的），
> 再做第 4 条（OLED，调参效率提升最大），其余按需要来。

## 七、移植检查清单

按顺序逐项确认：

- [ ] CubeMX 已生成 F4 的 `Drivers/` + 启动文件 + `.ld` + `hal_conf.h`
- [ ] `stm32f4xx_it.c` 中没有 `SysTick_Handler` / `EXTI0_IRQHandler` / `USART2_IRQHandler`
- [ ] CubeMX 生成的 `main.c` 已删除或排除出编译
- [ ] `make MCU_FAMILY=F4 -j8` 编译通过，无警告
- [ ] `make size` 确认 Flash / RAM 没超
- [ ] 烧录后心跳灯按预期闪（`PC13`）
- [ ] 串口能收到遥测帧（先确认波特率 9600）
