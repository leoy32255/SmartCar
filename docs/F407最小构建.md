# F407 修订3最小构建

范围：根据用户确认的修订3接线和 `.scratch/f407-classroom-baseline/spec.md`，提供保持停车的 F407 板级固件。用户已确认本次验证接口为构建产物及板级初始化。完整课堂交付中的控制/协议、传感器驱动、心跳超时和上位机由后续任务完成。

2026-10-05：板级基线继续沿用；新增XY-160D独立驱动及测试见 [F407电机驱动迁移](F407电机驱动迁移.md)。默认诊断固件仍只执行初始化并保持停车。

## 构建

依赖已随仓库固定，无需 CubeMX 生成。需要 Python 3、GNU Make、`arm-none-eabi-gcc`（含 newlib-nano）及 binutils。测试另需本机 GCC。

```sh
make -j8
make size
make test
```

默认 `MCU_FAMILY=F4`。产物：`build/F4/SmartCar.elf`、`.hex`、`.bin`、`.map`。Flash 起始地址 `0x08000000`。`make clean` 只清理本项目的 `build/F4`，拒绝重定向目录。可用 `CROSS_COMPILE` 指定工具链前缀；测试读取同名环境变量，用 `HOST_CC` 指定主机编译器。没有编译器时测试报错，不以跳过冒充通过。

Windows PowerShell 本机已验证的环境设置（只影响当前终端）：

```powershell
$env:PATH = 'C:/Users/21449/AppData/Local/stm32cube/bundles/gnu-tools-for-stm32/14.3.1+st.2/bin;D:/AppGallery/7.0/shellutils;' + $env:PATH
$env:HOST_CC = 'D:/AppGallery/Downloads/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/gcc.exe'
make -j8
make test
```

其他电脑按实际安装路径设置 PATH；仓库的 Makefile 不绑定本机路径。Mac/Linux 可用相同命令，但本轮未在这些系统实际运行。

## 资源与初始化

| 资源 | 配置与归属 |
|---|---|
| 时钟 | HSE 8 MHz，PLLM=8/N=336/P=2/Q=7；SYSCLK/AHB 168 MHz，APB1 42 MHz、APB2 84 MHz；48 MHz域由PLLQ提供，未启用应用USB |
| 电源/Flash/FPU | PWR Scale1先于PLL；Flash 5 WS；F407不调用OverDrive；官方SystemInit启用FPU并设置Flash向量基址 |
| TIM1 | PE9/PE11 AF1，PSC=83/ARR=999，2 kHz，两个CCR始终为0 |
| 左编码器 | PC6/PC7 AF2，TIM3 TI12，16位计数，无中断 |
| 右编码器 | PD12/PD13 AF2，TIM4 TI12，16位计数，无中断 |
| 控制节拍 | TIM6，84 MHz/(8399+1)/(49+1)=200 Hz，即5 ms；中断仅增加观测计数 |
| HAL时基 | SysTick 1 ms，仅HAL_IncTick；优先级15 |
| SPI2 | PB13/14/15 AF5，Mode0，APB1 /64=656.25 kHz；PB12 IMU CS、PE7 MCP23S17 CS均保持高，不发传感器事务 |
| IMU INT | PB10上升沿，下拉，EXTI15_10中仅处理line10；优先级3 |
| USART2 | PD5/6 AF7，9600 8N1；优先级2，仅读SR/DR清接收与错误状态并计数，不解析运动指令 |
| 保留 | PA0按键、PA1 LED、PA11/12 USB、PA13/14 SWD、晶振；未分配蜂鸣器，不配置这些引脚 |

`Core/Inc/bsp_config.h` 将F407转到 `bsp_f407.h`。`Core/F407` 是当前板级实现，显式源文件清单排除了旧 `Core/Src` 应用和旧ISR。SysTick、TIM6_DAC、EXTI15_10、USART2及故障处理器统一位于 `Core/F407/interrupts.c`。不得再生成同名强定义。TIM6_DAC的DAC部分未启用。

先开GPIO时钟，再预置PE8/10/12/13=1并配置输出，之后PE9/11=0；两CS也先预置高电平。此顺序在等待HSE之前执行。TIM1先配置并启动零占空比，再将PE9/11切为AF。所有HAL初始化错误进入Error_Handler，将方向置11、PWM引脚改为普通输出0后停留。上电至代码开始执行期间仍依赖图纸中的外部方向上拉，不能以软件证明该阶段电气状态。

最小主循环仅等待中断，无启动按键逻辑、自动运动、控制算法或串口运动命令。`bsp_control_ticks`、`bsp_imu_edges`、`bsp_uart_rx_bytes`、`bsp_uart_errors` 是调试观测量，不是已完成的蓝牙诊断协议。

板级初始化后调用 `Motor_Init` 保持软件禁用。`Bsp_MotorStop` 先方向11、再清CCR并产生TIM1更新事件，清除HAL配置的比较预装载；该函数供初始化/驱动内部使用，应用应调用撤销使能的 `Motor_Stop`。

## 启动与内存

官方 `startup_stm32f407xx.s` 完成数据搬运、BSS清零、SystemInit、C初始化及main入口。使用 `-nostartfiles` 避免同时引入通用CRT启动和无用系统调用；`_init` 是空的newlib初始化钩子。

链接脚本配置512 KiB Flash和128 KiB普通SRAM，栈顶 `0x20020000`，预留2 KiB栈。64 KiB CCM单独声明且不使用，不能把192 KiB全部当成连续SRAM。没有动态分配接口；栈预留不等于已验证最坏运行栈深度。

## 验证边界

- 产物测试检查Flash/栈地址、Reset和四个IRQ向量强定义、TIM4/EXTI0没有混入旧ISR、真实HAL符号、HEX校验和。
- 主机边界测试使用真实ST类型和宏，在主机模拟MMIO/HAL调用，执行实际Bsp_Init及Bsp_MotorStop，检查引脚AF、预置电平、时钟参数、编码器、PWM、节拍及IRQ资源分配。它没有执行真实HAL硬件初始化，不能证明时序或电气行为。
- 依赖测试核对所有71个上游文件哈希。真实固件交叉编译不使用桩。
- `.ci_check/check.sh` 仅保留旧F1语法预检；其结果不能替代F407真实编译。
- DFU烧录、台架、传感器、电机和实车均未执行。板载引脚占用、BOOT操作、8MHz晶振、XY参考电压、供电与编码器CPR仍按spec现场核验。

## 后续ROM DFU路径

STM32F407系统存储器内置USB DFU bootloader；不要求本应用加入USB DFU类。依据[ST AN2606](https://www.st.com/resource/en/application_note/an2606-introduction-to-system-memory-boot-mode-on-stm32-mcus-stmicroelectronics.pdf)的STM32F405/407章节，在取得本板BOOT/复位资料后进入系统存储器启动，用STM32CubeProgrammer确认USB DFU枚举，再选择上述BIN及地址0x08000000，下载并校验，恢复Flash启动后复位。

本板跳帽/按键顺序尚无原理图证据，此处不指定；USB与外部5V不直接并供。`make flash` / `make flash-ocd` 在F407目标明确报错，避免旧ST-Link目标被误当DFU流程。本轮不执行任何下载。
